What is in use, and what is still a design

The app in use today covers people, organization, CV review, and KPI. Project and Worksheet follow the product design and are not in the menu yet. The screens in this file are mockups of that design.

Order of the briefing
  • Where these functions sit beside People and KPI.
  • Opening a project, placing people, and keeping a load above 100% visible.
  • A flat work item, plus a file or a link.
  • A weekly worksheet, a one-hour minimum, and leave that adds no work hours.

Two layers, so the room is not promised the wrong thing.

KMPlus People is a people system with evidence: who someone is, the position they hold, a CV that has been reviewed, and this year's KPIs.

In use today
  • The list of people, positions, and the organization.
  • A CV changes a person's record only after HR accepts it.
  • This year's KPI: one's own portfolio, the manager queue, KPI Admin, and the KPI tree.
Shown here as mockups
  • A project for one client, or for KMPlus when the client name is blank.
  • People on the project, work items, and deliverables.
  • A worksheet, which is that person's own hour calendar.
  • Leave, sick time, and remote on the same sheet.

The example screens add a Work group to the menu. That group is not in the app that is running today.

Four things meet on one person.

A project is not a task board. A worksheet is not a leave list. They meet when a person who is staffed on a project records hours against one work item.

Project

A body of work with a code, a name, an optional client, a required start, and an optional end.

Staffing

A person on that project, with dates and a load in percent. This is not their position in the organization.

Work item

One named piece of work, with one person in charge and a start and an end. The row has no status.

Worksheet

Hours the person records. If those hours name a project, they name one work item.

A deliverable is a file or a link on the project. It may be attached to several work items, or to none. Status sits on the deliverable, not on the work item and not on the project.

Admin opens a project. A person records their own hours.

Admin is a grant given to chosen users. Holding HR does not make someone Admin. A person may still hold a KPI while they hold Admin.

Action Admin Person with staffing in progress Each person, for themselves

Admin also configures deliverable status labels, leave types, and time block types. The starter statuses are Draft, Shared, and Accepted. The starter time block types are Meeting and Activity. A label that is still in use cannot be removed.

Hours on a project are valid only when there is a work item and staffing covers that date. Hours with no project are still valid, and they still count in the type and in the week total. An invitation from someone else counts only after it is accepted.

This function is deliberately narrow.

In this design
  • A project with a code that can be changed, an optional client, and an optional end date.
  • Staffing with a load, including a load that passes 100%.
  • A flat work item with one person in charge.
  • A deliverable that is a versioned file or a link, with a status.
  • A weekly worksheet, time block types, and leave that appears without adding hours.
Not in this design
  • A Kanban board, a sprint, a ticket, or a parent work item.
  • A project health status, or a status on the work item.
  • A leave balance and a pay calculation.
  • A work block shorter than one hour.
  • Payslip. That is a separate module, and it is not part of this briefing.
Closing line

A project gives the work and its people a place. A worksheet gives evidence of the hours, including hours that are not attached to a project, and leave that may be taken without counting as work hours. The screens in this file are mockups of that design.
