# Admin is a User grant, not an exclusive login hat

**Admin** is a grant on chosen Users. It covers KPI governance, and it covers opening a **Project** and maintaining that Project’s **ProjectCode**, name, client name, and dates. Any Admin may change those fields on any Project. It also covers **Staffing**: any Admin may add a Person, end that row, or delete a row that was a mistake. Admin configures the **DeliverableStatus** labels, the **LeaveType** labels, and the **TimeBlockType** labels for the Tenant, and may add, rename, or remove a **PublicHoliday**, including refreshing Indonesia holidays into that list (see ADR-0008). Any Admin may file a **LeaveRequest** for another Person and may decide one: unpaid, paid, or refused. It may stack with Employee or Manager so that Person can still hold a **KpiPortfolio**. HR and Tenant admin do not imply Admin. HR or an existing Admin grants or revokes it; several Users may hold it.

We rejected a fourth exclusive login hat (that would stop the Admin from being a pekerja) and rejected treating today’s Tenant admin as KPI Admin by default. We rejected a separate grant only for opening a Project, and a separate grant for project reports, because the same people already hold Admin. Time-block types, the read-only project and timesheet reports, and the all-staff view of approved leave are this same grant. HR does not receive them unless that Person also holds Admin.
